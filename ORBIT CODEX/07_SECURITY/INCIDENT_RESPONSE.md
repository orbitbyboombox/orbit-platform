# Incident Response

1. Clasificar severidad y preservar evidencia/timestamps.
2. Contener el acceso afectado sin destruir datos.
3. Identificar fuente canónica y alcance.
4. Informar al Founder; rotaciones y restores requieren autorización.
5. Recuperar desde proveedor oficial/baseline.
6. Validar integridad, seguridad y operación.
7. Documentar causa, impacto, acciones y prevención sin secretos.

P0: pérdida de datos, acceso no autorizado o caída crítica. P1: flujo Founder/financiero bloqueado. P2/P3: degradación no bloqueante.
